# Windows port: соответствие оригиналу и проверки

Этот документ составлен по исходникам `siliconbag/under-the-rug`, доступным в исходном репозитории. Он описывает поведение оригинала и ориентиры переноса. Таблица ниже не является отчётом о пройденных проверках Windows-сборки.

## Поведение оригинала и целевой перенос

| Возможность | Что делает версия Mac | Ориентир для Windows |
| --- | --- | --- |
| Рабочий стол | Прозрачное окно над значками и под обычными окнами; используется первый экран | Окно WPF с прозрачностью, привязанное к оболочке Explorer; один выбранный экран, по умолчанию основной |
| Физика | XPBD, 44 столбца сетки, 10 подшагов; растяжение, сдвиг, изгиб, дальние привязи от захвата; самоколлизии и трение | Перенос решателя в C#, сохранение ограничений и проверки конечности чисел |
| Мышь | Захват ближайшей вершины верхнего треугольника, подъём на 120 точек, колесо поворачивает ткань | Собственная проверка попадания по той же проекции, захват мыши до отпускания |
| Пропуск кликов | Клики вне ткани попадают на рабочий стол; тень не считается тканью | Переключение нативного пропуска ввода по сетке; не перехватывать уже начатое перетаскивание файла |
| Значки | Accessibility/Finder дают координаты; из значков строится плавно меняющаяся карта высот | Чтение координат значков Explorer, перевод в координаты WPF; обновление при изменении стола |
| Смести и вернуть | Сохраняет исходные координаты в настройках до первого сметания; возвращает их по именам | Сохранять устойчивый идентификатор и координаты до изменения, сохранять резервную копию при ошибке |
| Автоупорядочивание | Операция блокируется, если Finder сам сортирует значки | Предупреждать при включённом автоупорядочивании Explorer; не выключать его молча |
| Сетка Windows | Аналога нет | Для сметания и восстановления нужно отключить «Выровнять значки по сетке»: иначе стандартный список Windows округляет позиции и может раздвигать соседние значки. Проверять до любых перемещений; настройку сетки не менять |
| Оформление | 4 ковра, 3 варианта пола; загрузка своего изображения в каталог поддержки приложения | Использовать исходные ресурсы; свои изображения копировать в постоянный пользовательский каталог |
| Обои | До первого изменения запоминает прежний путь и даёт команду восстановления | Сохранять прежний путь и физическую копию, применять проверенный BMP через IDesktopWallpaper, публиковать в постоянном кэше стандартного каталога тем Windows |
| Настройки | Открываются при запуске и повторном запуске; закрытие окна оставляет ковёр | Окно настроек, значок области уведомлений и один экземпляр приложения |
| Автозапуск | В исходном интерфейсе не предусмотрен | Настройка для текущего пользователя; тихий --startup, сохранённая поза, ожидание готовности Explorer. Повторный обычный запуск открывает настройки через скрытое окно сообщений |
| Положение | Хранит нормализованный центр и угол; размер сохраняется отдельно | Сохранять центр относительно экрана, проверять диапазоны и доступность после смены дисплея |
| Покой | После 45 спокойных кадров останавливает рендер; сохраняет позу; проверка наведения 30 Гц, значков каждые 4 с | После 45 спокойных кадров останавливать основной цикл; дополнительно учитывать перемещение за весь кадр, чтобы контактное дрожание на буграх не мешало покою; лёгкие таймеры остаются |
| Графика | Metal, мягкие PCSS-тени, рельеф шерсти из текстуры, приглушённая изнанка | WPF 3D требует собственного приближения теней/освещения; визуальное совпадение Metal не следует заявлять без реализации шейдеров |
| Служебные режимы | `--demo`, `--settings-shot`, `--floor` | Проверять и описывать только реально реализованные режимы Windows |

Оригинал тоже ограничен первым экраном; поддержка нескольких мониторов не является обязательным условием сохранения его текущего поведения. На Mac у стопок выше бугры; у стандартного рабочего стола Windows нет прямого аналога Finder Stacks.

## Важные ограничения WPF и Win32

- `AllowsTransparency=true` требует `WindowStyle=None`. Прозрачный фон сам по себе не делает окно прозрачным. [Window.AllowsTransparency](https://learn.microsoft.com/en-us/dotnet/api/system.windows.window.allowstransparency)
- Нулевой alpha у layered-окна пропускает мышь; `WS_EX_TRANSPARENT` пропускает события для всего окна. Одна лишь команда `HTTRANSPARENT` документирована как поиск нижележащего окна **того же потока**, поэтому её нельзя считать достаточной гарантией передачи клика Explorer другого процесса. [Layered Windows](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features), [WM_NCHITTEST](https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-nchittest)
- Layered child windows поддерживаются начиная с Windows 8. Привязка к внутренней иерархии `Progman`/`WorkerW`/`SHELLDLL_DefView` зависит от реализации Explorer и требует проверки после перезапуска оболочки и на поддерживаемых версиях Windows. Публичная документация `SetParent` сама по себе не обещает стабильности этих классов оболочки. [Window Features](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features)
- `SetParent` не меняет `WS_CHILD` и `WS_POPUP`. Разные DPI-контексты родителя и дочернего окна могут приводить к сбросу DPI-awareness процесса; следует проверять результат привязки и фактический размер/масштаб окна. [SetParent](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setparent)
- Для процесса предпочтительно задавать DPI-awareness манифестом до создания окон. Координаты значков/курcора Win32 и размеры WPF нужно приводить к одним единицам. Проверки нужны при 100%, 125%, 150%, 200%, а также при переносе основного дисплея. [DPI awareness](https://learn.microsoft.com/en-us/windows/win32/hidpi/setting-the-default-dpi-awareness-for-a-process)
- WPF `PerspectiveCamera.FieldOfView` задаёт горизонтальное поле зрения. Для формулы оригинала `D=max(W,H)*1.15` нужен угол `2*atan(W/(2*D))*180/PI`; камера в `(W/2,H/2,D)`, взгляд вдоль `-Z`, вертикаль `+Y`. Для координат мыши требуется разворот экранной оси Y. Собственная проекция для hit test должна совпадать с камерой. [PerspectiveCamera.FieldOfView](https://learn.microsoft.com/en-us/dotnet/api/system.windows.media.media3d.perspectivecamera.fieldofview)
- Для WPF 3D полезны общие индексируемые вершины, повторное использование моделей, `Freeze()` для неизменных ресурсов и отключение штатного hit test у `Viewport3D`, если используется собственный picker. Microsoft рекомендует держать отдельную сетку в пределах 20 001 позиции и 60 003 индексов. [Maximize WPF 3D Performance](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/graphics-multimedia/maximize-wpf-3d-performance)

## Контрольный список ручной приёмки

Это план приёмки, а не утверждение об уже выполненных тестах.

1. Запустить из распакованного каталога с пробелами и кириллицей; убедиться, что открылись настройки и появилась ткань. Закрыть настройки, открыть их из области уведомлений и вторым запуском EXE. Проверить выход.
2. Проверить, что ковёр перекрывает значки и остаётся под окнами Проводника/браузера. Проверить Win+D, Win+M, переключение приложений, виртуальный рабочий стол, блокировку и разблокировку, перезапуск Explorer.
3. Кликнуть, выделить рамкой и открыть файл в пустой части стола, за тканью и в области только тени. Начать перетаскивание значка вне ковра и провести через ковёр: приложение не должно забирать такой жест.
4. Поднять каждый угол, середину и край; быстро потянуть и отпустить за пределами окна. Ковёр не должен оставаться захваченным после Alt+Tab, открытого меню или потери capture. Повернуть колесом в обоих направлениях; проверить видимую изнанку и складки.
5. Создать/передвинуть/удалить значок; проверить обновление бугра. Повторить с маленькими и большими значками и с нестандартным масштабом дисплея. Значки второго экрана не должны ошибочно давать бугры на первом.
6. Смести значки при выключенном автоупорядочивании, закрыть и повторно запустить приложение, вернуть расположение. Повторное сметание не должно затирать первую резервную копию. Удалённый, новый или переименованный значок не должен приводить к сбросу остальных.
7. Проверить включённое автоупорядочивание и ошибки доступа Explorer: показать понятное сообщение, сохранить данные восстановления. Файлы не должны перемещаться или удаляться на диске.
8. Поочерёдно выбрать 4 ковра и 3 пола; вернуть прежние обои. Загрузить JPEG/PNG, закрыть приложение, удалить исходную картинку и запустить снова. Неподдерживаемая/повреждённая/очень большая картинка не должна завершать приложение.
9. Проверить размер, центрирование, повторное падение, накрытие значков, сохранённые центр/угол/текстуру/размер после перезапуска и смены разрешения.
10. Измерить загрузку CPU и GPU во время движения и после покоя; убедиться, что нет постоянного перерисовывания, накопления памяти и активного busy loop. Оставить приложение открытым и повторить несколько сотен операций.
