# Проверки Windows-переноса

Проверено 27 октября 2026 года на Windows 11 x64 (сборка 26300), .NET Framework 4.8, масштаб основного экрана 125%, WPF hardware rendering tier 2. Windows 10 — целевая платформа, отдельного запуска на ней в этой среде не было.

## Автоматические проверки

- Системный C#-компилятор собирает EXE x64 без загрузки зависимостей.
- Физика: 5 594 проверки. Падение, проекция и выбор верхнего треугольника, захват и отпускание, поворот, бугры, столкновения слоев ткани, восстановление после некорректных чисел. Сценарий с 90 плотными буграми прогоняется 600 кадров; проверяется переход в покой и отсутствие ложного покоя во время падения или захвата.
- Позиции значков: 15 защитных проверок, либо 47 вместе с нативной проверкой. Отдельный невидимый процесс создает настоящий `SysListView32`. Проверяются межпроцессные буферы, Unicode, одинаковые подписи, координаты больше 16 бит, отказ до перемещений при сетке/автоупорядочивании, повторное сметание без перезаписи копии, сохранение новых значков, восстановление после смены индексов, частичное восстановление и повторная попытка.
- Нативные тесты работают с собственным списком, не с рабочим столом пользователя. После проверки тестовые процессы закрываются.
- Обои версии 1.0.1: 67 изолированных проверок. Проверяются полное декодирование JPEG и публикация RGB24 BMP, отказ до системных изменений при битом изображении, сохранение первой копии между переключениями и перезапусками, восстановление после частичной ошибки, миграция старого JPEG при пустом ответе COM и перенос резервных изображений в доступный оболочке кэш тем.
- Автозапуск версии 1.1.0: 34 изолированных проверки. Кавычки и абсолютные пути, пробелы и Unicode, проверка существования EXE до записи, ограничение длины команды, включение/отключение без затрагивания других записей и обновление пути после перемещения. Эти тесты используют подставное хранилище и не меняют реальный реестр.

## Проверка приложения

Приложение запускалось вне песочницы на реальном рабочем столе Explorer. Проверены существование и видимость HWND ковра, его родительская связь с рабочим столом, окно настроек, чтение 90 настоящих значков, открытие настроек при повторном запуске EXE, остановка анимации после оседания и штатный выход.

В отчете smoke-test получено: `Attached=True`, `Visible=True`, `Finite=True`, `SettingsReopenedBySecondLaunch=True`, `Sleeping=True`, `Dpi=1.25`.

Служебный рендер со складкой и изображение окна настроек сохранены в PNG и визуально просмотрены. При первоначальной проверке запуска значки пользователя и обои не изменялись.

## Исправление фона в 1.0.1

Чёрный фон воспроизведён на реальном рабочем столе, в том числе при скрытом окне ковра. Исходные JPEG и подготовленные BMP исправны. Файлы из прежнего каталога данных программы не принимались оболочкой: `IDesktopWallpaper.SetWallpaper` возвращал `0x80070002`. Те же байты из стандартного каталога тем Windows успешно применялись. Кэш перенесён в `%APPDATA%\Microsoft\Windows\Themes\UnderTheRugWindows`.

Через код исправленного сервиса поочерёдно применены все три пола, затем восстановлено исходное изображение обоев и снова применён выбранный дубовый пол. Путь и SHA-256 исходного изображения сохранены; системный API подтверждает активный BMP в новом постоянном кэше. Проверка выполнялась на конфигурации с двумя активными мониторами (125% и 100%); снимки реального фона сохранены во временный каталог для визуальной проверки. Значки пользователя не перемещались.

## Пределы проверки

Автотесты не заменяют приемку всех жестов на разных конфигурациях Windows. Ручные сценарии для Win+D, виртуальных столов, перезапуска Explorer и длительной работы перечислены в `PORTING-NOTES.md`; весь этот набор не объявляется пройденным.

Команда повторения основных и нативных проверок:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -NativeTests
```
